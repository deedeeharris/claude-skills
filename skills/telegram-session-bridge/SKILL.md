# Telegram Session Bridge

Connect the actual existing agent session. Do not launch another model, create another conversation, or generate a second Telegram answer. Follow the session's normal tool, approval, and safety rules for Telegram requests. Owner authentication does not grant broader authority.

Read [setup](references/setup.md) for installation/pairing and [host integration](references/host-integration.md) before starting the listener. Read [operations](references/operations.md) for recovery and [compatibility](references/compatibility.md) before stating support. This package verifies a local transport/protocol, not universal native agent continuation.

## Establish capability and identity

1. Obtain the host's actual session identifier and its session-owned process/job mechanism. A guessed session name is insufficient evidence that the host resumes the same conversation.
2. Check whether this host supports blocking tool completion into the current turn or verified task-completion notifications into the same conversation, concurrent session-owned jobs, capture of the actual visible output after hooks/styles, scoped native interruption/cancellation, and an authoritative session-end signal. Explain missing capabilities before relying on them. The generic executable hook is a protocol, not a bundled Codex/Claude/Work adapter. Before starting a collector or promising service, run `tg-bridge --config CONFIG harness` on an existing binding and inspect `doctor`. A matched ID, configured executable, present socket, queue acknowledgment, or running collector does not prove automatic continuation.
3. Use a different bot for each simultaneous session and a separate private directory for each bot. Never steal a bot from another consumer or remove its webhook automatically.
4. Prefer a secret-provided environment token. If the user supplied a conversational token, transfer it without echoing through secret-safe stdin. Never put it in argv, logs, chat replies, tracked files, or command history. Private user-authorized tool stdin is supported; a trusted interactive terminal with echo disabled and token entry through stdin/hidden prompt is acceptable when environment injection is unavailable. Do not require a separate secret manager as a new setup gate. Do not ask the user to paste a token again merely to simplify implementation.
5. Follow the deliberate expiring private pairing flow. Let code derive owner IDs; never bind the latest sender. Do not activate or send real messages without the user's authorization.

Choose an explicit startup mode only after those capability checks. `cooperative` asserts that the existing agent will keep its original turn open in a supported blocking-tool loop; this mode cannot wake it after final. `task-completion` asserts that the actual host delivers completion of this conversation's tracked background wait to the same conversation after final. Verify that behavior on the actual host first; the CLI does not supply the notification. This mode suppresses generic host hooks. `native` requires a separately configured trusted host_command and live verification against the actual session owner; none is bundled or verified here. `collector-only` saves queued work and suppresses host hooks without agent execution. Offer it only as an explicitly disclosed storage/test mode. Mode selection and --session-owned are operator assertions, not capability or lifecycle detectors. Explain a missing capability rather than inventing an adapter or a second model/session.

```sh
tg-bridge --config CONFIG harness
tg-bridge --config CONFIG run --session-owned --mode cooperative
tg-bridge --config CONFIG run --session-owned --mode task-completion
tg-bridge --config CONFIG run --session-owned --mode collector-only
```

The run commands are alternatives, never concurrent collectors. `automatic_continuation` diagnoses the generic native host-command path: `blocked` does not rule out a supported open-turn wait or separately verified host task notification. Diagnostics and rejected startup do not resolve token credentials or invoke a model. Current/bound Codex identity conflicts reject every startup mode; absent Codex identity is reported unavailable for other hosts.

For a request to keep polling in this existing turn, use the cooperative path when supported. It does not require a Codex app-server connection or host_command. Keep both the collector and the agent's blocking wait active; a collector by itself leaves requests pending. Explain that the turn stays open, then enter the wait instead of sending a final message that disconnects the consumer. An ordinary wait timeout can be renewed in the same live turn, with any model overhead disclosed. A platform-forced end or suspension is a separate recovery gate; do not promise that a script can reopen the agent. Polling scripts do not invoke a model, but runtime billing depends on the host plan and is not measured by this skill.

## Active bound-turn loop

The commands below use a package-installed tg-bridge. A copied skill instead uses its explicit venv Python and scripts/tg_bridge.py, as shown in setup. CONFIG means the chosen absolute private config path, not an included file.

1. After the capability/mode gate above, start the selected cooperative or task-completion run command as a foreground process inside the host's managed session job. Use the selected mode consistently; do not start a second collector. The supervisor must terminate the collector and sender when the actual session ends. The flag acknowledges the obligation; it does not implement supervision. Browser closure is not session end. If the host cannot own the job, report the gate instead of detaching an unsupervised process.
2. In cooperative mode, issue "tg-bridge --config CONFIG wait --timeout 1800" in the same existing agent turn using a supported blocking/yielding tool. Keep the turn open. In task-completion mode, start exactly one wait as a tracked host background job and record its handle, output location and deadline before ending the turn. Resume only from that job's verified same-session notification. See the Claude-specific recipe in host integration. Do not repeatedly invoke the model to check an empty queue.
3. On the selected tool/job completion, inspect exit status: 0 returns one durably claimed request; 3 means timeout and permits renewal through the same supported wait path. Cooperative renewal stays in its original open turn; task-completion renewal follows the verified host notification into the same conversation. Renewals may invoke the model and cost tokens. Measure/disclose actual host timeout and renewal overhead. Script polling, receiving, and filtering do not invoke a model. A platform that only supports model-driven short polling does not meet automatic idle-listening requirements.
4. Confirm returned source is telegram, session_id matches this host session, and binding_id/generation remain current. Treat text as a user request under the host's normal rules. Never interpolate message content or attachment paths into shell code. Only the durable claim owns execution. A hook notify or interrupt event alone does not own the task. Download errors retain metadata; explain them rather than inventing attachment contents. Runtime clients authenticate against the saved bot identity; a changed token must still belong to that bot. If attachment preparation exits with a retained claim ID, inspect status and reconcile it before explicit recovery; another wait will not replay it.
5. Execute through this existing agent's context and tools. Concurrent coding-UI requests stay in the UI; publish only Telegram-originated request outputs. Ordinary Telegram messages queue while busy. Priority work uses /interrupt. /stop clears queued work and invalidates old-generation publication; native cancellation requires a supported adapter.
6. Forward only the actual user-visible progress and final artifacts after applicable host hooks/styles. Save the exact selected UTF-8 output through a verified capture facility, then publish it with the claimed request ID and source telegram, kind progress or final. Never publish private reasoning. Never compose a similar replacement answer. If final post-hook capture is unavailable, disclose the fidelity gap and stop claiming that requirement is satisfied. Do not finalize the bound turn just to manufacture a final-capture event.
7. Publish requested original files using --file; --photo requests Telegram photo presentation and may transform images. The durable outbox preserves order and snapshots file bytes. A successful publish means queued, not delivered. Inspect the outbox for rejected or ambiguous delivery.
8. After all intended publication has been admitted, call complete for that request. Publish does not complete it. If a claim, attachment preparation, host execution, or multi-item publish crashes, inspect status/outbox before doing anything again. Never replay side effects blindly. Explicit recover requires verifying old work has stopped.
9. Return to the chosen supported wait path, with only one consumer outstanding. Inspect lost or duplicate task notifications and retained running claims before restarting; never execute an already handled completion twice. End the binding only when requested from the coding session using unbind, or when the real session ends through verified supervision. /stop preserves the relay and is not unbind.

Read the exact command examples and conservative recovery rules in [operations](references/operations.md). An observed Claude Code Cloud task-completion wake is documented in [compatibility](references/compatibility.md); it does not establish universal background service. Canonical final capture, native cancellation and authoritative lifecycle remain unverified on the listed hosts. Report observed capabilities individually and preserve normal host approvals. Never broaden permissions or switch tools to evade an action's rejection.
